## Архитектурные решения

### 1. Единая база данных

**Таблицы из обоих проектов объединены:**

```
profiles (auth users)
├── Профили пользователей
├── Роли (admin/manager/employee)
└── Связь с facilities

facilities (из webURVS)
├── Объекты/филиалы
└── Привязка к администратору

employees (из webURVS)
├── Сотрудники
├── Привязка к facilities
└── Привязка к positions

positions (из webURVS)
├── Должности
└── Привязка к facilities

shift_templates (из v0-staff-schedule-generator)
├── Шаблоны смен
└── Привязка к facilities

schedules (объединено)
├── Расписания сотрудников
├── Из v0-staff-schedule-generator
└── Привязка к facilities, employees, shift_templates

timesheets (из webURVS)
├── Табелирование
├── Отметка прихода/ухода
└── Статус (pending/approved/rejected)
```

### 2. Контроль доступа (Role-Based Access)

```
Admin
└── Полный доступ ко всему
    ├── Управление объектами
    ├── Управление должностями
    ├── Управление сотрудниками
    ├── Управление шаблонами смен
    └── Управление расписаниями

Manager
└── Доступ к своему объекту
    ├── Просмотр расписания своей команды
    ├── Табелирование сотрудников
    ├── Управление командой
    └── Просмотр статистики

Employee
└── Доступ только к своим данным
    ├── Просмотр своего графика
    └── Просмотр своих табелей
```

### 3. API унификация

**Все API маршруты в одном месте: `/app/api/`**

| Функция | Маршрут | Метод |
|---------|---------|-------|
| Логин | POST /api/auth/login | POST |
| Регистрация | POST /api/auth/sign-up | POST |
| Логаут | POST /api/auth/logout | POST |
| Объекты | /api/facilities | GET, POST |
| Должности | /api/positions | GET, POST |
| Сотрудники | /api/employees | GET, POST |
| Расписания | /api/schedules | GET, POST |
| Табели | /api/timesheets | GET, POST |

## Миграция данных

### Если у вас были данные в старых проектах

1. **Экспортируйте данные из старых БД**
```bash
# Из webURVS (PostgreSQL)
pg_dump -U user -d database > backup.sql

# Из v0-staff-schedule-generator (если был)
sqlite3 database.db .dump > backup.sql
```

2. **Адаптируйте структуру к новой схеме**
   - Соответствие типов данных
   - UUID вместо INT для ID
   - Правильные связи между таблицами

3. **Импортируйте в Supabase**
   - Через SQL Editor в Dashboard
   - Или используйте Supabase CLI

## Функциональность, добавленная при объединении

### 1. Row Level Security (RLS)
- Все таблицы защищены
- Пользователи видят только разрешённые данные
- Менеджеры видят только свой объект

### 2. Статусы табелей
- Pending (ожидает подтверждения)
- Approved (одобрено)
- Rejected (отклонено)

### 3. Интеграция расписаний и табелей
- Табель может быть привязан к расписанию
- Автоматический расчет отклонений

### 4. Админ-панель с единым интерфейсом
- Все управление в одном месте
- Интуитивный UI
- Быстрый доступ ко всем функциям

## Возможные вопросы

**Q: Что случилось с Express.js от webURVS?**  
A: Функциональность перенесена на Next.js API Routes. Это позволяет иметь единый codebase и упрощает развёртывание.

**Q: А что с генератором расписаний из v0-staff-schedule-generator?**  
A: Интегрирован в `/app/dashboard/schedules`. Теперь это часть админ-панели.

**Q: Как обрабатываются конфликты данных при миграции?**  
A: Если у вас есть старые данные, нужно адаптировать их структуру к новой схеме.

**Q: Какой уровень доступа по умолчанию?**  
A: При регистрации новый пользователь получает роль 'employee'. Админ должен изменить роль в БД.

**Q: Можно ли откатиться на старую версию?**  
A: Да, данные в Supabase полностью совместимы. Можно запустить старое приложение с той же БД.
